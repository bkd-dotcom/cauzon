# Sample outputs

These are **real dossiers generated by Cauzon** (not hand-written), so judges can
evaluate output quality without running the code.

- [`nyc-taxi-freshness-incident.md`](./nyc-taxi-freshness-incident.md) — a
  **freshness-propagation** incident. The visible symptom is a 40% volume drop on
  `daily_revenue`, but Cauzon traces past the intermediate `trips_cleaned` node
  to the true origin: `raw_trips` ingestion stalled 2 days ago. Note the
  **verifiable proof path** and the captured transform SQL.

- [`shop-schema-change-incident.md`](./shop-schema-change-incident.md) — a
  **silent schema-change break**. `weekly_sales` reports $0 revenue everywhere
  even though order volume looks normal. Cauzon traces the fault to `raw_orders`,
  where the column `amount` was renamed to `order_amount` — while the downstream
  transform still selects `amount AS revenue`. The captured transform SQL is the
  smoking gun. This is a fault no freshness/volume alert would catch.

Each dossier is what Cauzon writes back into DataHub via `save_document`, and is
attached to the incident + the culprit asset (which is also tagged `root-cause`).

## Live write-back proof

[`live-proof/`](./live-proof/) contains **raw evidence captured from a running
DataHub instance** confirming Cauzon's write-backs actually landed — the tags,
the updated description, the dossier document, and the real lineage chain it
traversed. See [`live-proof/README.md`](./live-proof/README.md).

To regenerate:

```bash
# freshness scenario (default)
PYTHONPATH=agent python3 -m cauzon.cli
# schema-change scenario
CAUZON_MOCK_SCENARIO=schema_change PYTHONPATH=agent python3 -m cauzon.cli
```
