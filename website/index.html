Trace a data incident to its
root cause — and prove it.

Cauzon is an agent that investigates data incidents on DataHub. It walks lineage upstream to find where a problem started, verifies the cause against the lineage graph before reporting it, and writes the finding back to the catalog so it isn't lost.

View source How it works

Why this exists

When a dashboard shows the wrong numbers, the alert tells you something broke — not what. Someone still has to open the lineage graph, work upstream table by table, diff schemas, and read the transformation SQL until they find the origin. It's slow, it happens repeatedly, and the reasoning is thrown away afterward.

A language model can do this traversal, but on its own it tends to name a plausible-sounding cause it can't substantiate. Cauzon's constraint is simple: it only reports a cause it can connect to the symptom with an actual path through the lineage graph. If it can't find that path, it says so rather than guessing.

How it works

Five steps, each backed by a DataHub tool call through the MCP Server.

  1. 1

    Detect

    Resolve the reported symptom — a failing assertion, a stale table, a wrong dashboard — to a specific dataset.

    search incidents

  2. 2

    Scope

    Fetch the upstream lineage, limited to a few hops, so the search stays bounded to the datasets that could plausibly be responsible.

    get_lineage

  3. 3

    Rank candidates

    Score each upstream dataset on freshness lag, row-count change, recent schema changes, and changes to its defining query. The origin usually sits furthest upstream, not at the first table that looks wrong.

    get_entities list_schema_fields

  4. 4

    Verify the path

    Before accepting a candidate, reconstruct the lineage path from it to the symptom and pull the transformation SQL along the way. No path means the candidate is rejected — not reported.

    get_lineage_paths_between get_dataset_queries

  5. 5

    Write back

    Save the incident write-up as a document, tag the responsible dataset, and update its description — so the next person, or the next agent, starts from what was already learned.

    save_document add_tags update_description

Design notes

It refuses to guess

A ranking is a hypothesis. Cauzon only reports a root cause once it has reconstructed the lineage path connecting it to the symptom. When no path can be found, it reports that and stops, rather than writing an unsupported claim into a shared catalog.

It looks for the origin

The table that looks broken is usually a victim, not the cause. The scoring prefers the dataset furthest upstream that still shows a strong signal — the point where the fault actually entered the pipeline.

The same core runs anywhere

The investigation loop is a plain Python module. It runs against a live DataHub through the MCP Server, or against a bundled mock with two planted-fault scenarios so the project can be run and tested without any infrastructure.

It tolerates a lagging index

DataHub's lineage search depends on a graph index that can fall behind. When it returns nothing, Cauzon falls back to reading the stored lineage aspects directly, so an investigation still completes.

Approach

The verify-the-path requirement follows a line of recent root-cause-analysis work arguing that a diagnosis is only useful if the causal path behind it can be checked, not just asserted. Cauzon applies that idea to data lineage: the path is the explanation.

  • RCAFlow hierarchical multi-agent root-cause planning (AAAI 2026)
  • RCRank multimodal ranking of root causes (VLDB 2025)
  • OpenRCA / PAVE penalizing unverified diagnosis paths (2026)
  • DeepRoot separating grounding from reasoning (ICML 2026)

Try it

Runs against the bundled mock with no setup, or against a local DataHub.

# clone and install
git clone https://github.com/bkd-dotcom/cauzon
cd cauzon && pip install -e .

# run an investigation against the bundled mock
python -m cauzon.cli --scenario freshness

# or point it at a live DataHub
export CAUZON_DATAHUB_BACKEND=mcp
export DATAHUB_GMS_URL=http://localhost:8080
export DATAHUB_TOKEN=<token>
python scripts/run_live_writeback.py
