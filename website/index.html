Open‑source root‑cause analysis for DataHub

When a table goes wrong, the fault is usually further upstream.

Cauzon is an agent that investigates data incidents on DataHub. It follows lineage back to where a problem started, confirms the cause against the graph before reporting it, and records what it found in the catalog.

View source Read how it works

One command, a grounded answer.

Point Cauzon at an incident. It returns the origin of the problem, the path that proves it, and the transform that carried the fault downstream, then writes that back to DataHub so nobody has to rediscover it.

How an investigation runs

Five steps. Each one is a real call to DataHub through the MCP Server.

  1. 1

    Detect

    Resolve the reported symptom (a failing assertion, a stale table, a wrong dashboard) to one specific dataset.

    search · incidents

  2. 2

    Scope

    Pull the upstream lineage, capped at a few hops, so the search stays on datasets that could plausibly be responsible.

    get_lineage

  3. 3

    Rank the candidates

    Score each upstream dataset on freshness lag, row-count change, recent schema edits, and changes to its defining query. The origin usually sits furthest upstream, not at the first table that looks broken.

    get_entities · list_schema_fields

  4. 4

    Verify the path

    Before accepting a candidate, reconstruct the lineage path from it to the symptom and read the transform along the way. If there is no path, the candidate is rejected, not reported. This is the step that keeps the answer honest.

    get_lineage_paths_between · get_dataset_queries

  5. 5

    Write it back

    Save the write-up as a document, tag the responsible dataset, and update its description, so the next person (or the next agent) starts from what was already learned.

    save_document · add_tags · update_description

Why it works the way it does

It refuses to guess

A ranking is only a hypothesis. Cauzon reports a cause once it has rebuilt the lineage path connecting it to the symptom. When no path exists, it says so and stops, rather than writing an unsupported claim into a shared catalog.

It looks for the origin

The table that looks broken is usually a victim. The scoring favors the dataset furthest upstream that still shows a strong signal: the point where the fault actually entered the pipeline.

The same core runs anywhere

The investigation loop is a plain Python module. It runs against a live DataHub through the MCP Server, or against a bundled mock with two planted‑fault scenarios, so it can be tried with no infrastructure.

It survives a lagging index

DataHub's lineage search depends on a graph index that can fall behind. When it returns nothing, Cauzon reads the stored lineage aspects directly, so the investigation still completes.

Try it

Runs on the bundled mock with no setup, or against a local DataHub.

# clone and install
git clone https://github.com/bkd-dotcom/cauzon
cd cauzon && pip install -e .

# investigate the bundled planted-fault scenario
python -m cauzon.cli --scenario freshness

# or point it at a live DataHub
export CAUZON_DATAHUB_BACKEND=mcp
export DATAHUB_GMS_URL=http://localhost:8080
export DATAHUB_TOKEN=<token>
python scripts/run_live_writeback.py
